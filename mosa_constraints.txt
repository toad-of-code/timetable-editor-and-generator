              TIMETABLE SOLVER — MOSA CONSTRAINT REFERENCE
═══════════════════════════════════════════════════════════════════

File: src/utils/scheduler.ts
Solver: Multi-Objective Simulated Annealing (MOSA)
Objective = Minimize (Penalty Component) and Minimize (Robustness CV)


───────────────────────────────────────────────────────────────────
                        HARD CONSTRAINTS
───────────────────────────────────────────────────────────────────
  These are strictly enforced during the initial generation and 
  perturbation phases. A schedule violating these is rejected.

  1. DAY BOUNDARY
     Rule: An event (e.g., 2-hour practical) must start and end on the
           same day. It cannot span overnight.

  2. BREAK CONTINUITY (LUNCH PROTECTION)
     Rule: Multi-slot events (like 2-hour labs) must be continuous. 
           Because the 13:00-14:00 timeblock is intentionally missing 
           from the TimeSlots array, any class that starts at 12:00 
           would end at 14:00, creating an invalid jump. The solver 
           rejects these placements to protect the lunch break.

  3. ENTITY NON-OVERLAP (PROFESSOR & STUDENT GROUP)
     Rule: A Professor can only teach one class at a time.
           A Student Group can only attend one class at a time.
           (Checked via time overlap math: start1 < end2 && end1 > start2).

  4. ROOM SUITABILITY & NO DOUBLE BOOKING
     Rule: Practical sessions MUST go to a 'Lab'. 
           Lectures and Tutorials MUST go to a 'Lecture' room.
           The room must be empty during the requested time.
           The rooms capacity should be >= the student group size during search.
           If a fixedRoomId is specified, the event is locked to that room.


───────────────────────────────────────────────────────────────────
                        SOFT CONSTRAINTS (PENALTIES)
───────────────────────────────────────────────────────────────────
  These are optimized during the simulated annealing loop. Violations
  add varying weights to the penalty score.

  1. ROOM CAPACITY OVERFLOW
     Rule:    If a group is somehow placed in a room smaller than its size,
              add a penalty equal to the overflow count.
     Penalty: +(Group Size - Room Capacity) per slot.

  2. MINIMUM WORKING DAYS (SPREAD)
     Rule:    Avoid cramming a subject entirely into 1 day. 
     Penalty: +5 if a subject only spans 1 day.

  3. ROOM STABILITY
     Rule:    Prefer keeping the same subject in the same room throughout 
              the week to avoid students wandering.
     Penalty: +(Number of unique rooms - 1) per subject.

  4. STUDENT DAILY WORKLOAD FATIGUE
     Rule:    Prevent students from being overworked in a single day.
     Penalty: +2 weight for every hour over 4 hours.
              +10 weight for every hour over 6 hours.

  5. AFTERNOON LAB PREFERENCE
     Rule:    Practicals should ideally happen in the afternoon.
     Penalty: +100 if Practical starts before 13:00.
              -50 (Reward) if Practical starts after 13:00.

  6. GAP-LESSNESS (PSEUDO-HARD CONSTRAINT)
     Rule:    Compress the students' timetable so they don't have empty 
              free hours between classes. (Lunch break is exempt).
     Penalty: +10,000 for every free gap between classes. This massive 
              penalty forces the optimizer to act as if gaps are mathematically
              impossible.


───────────────────────────────────────────────────────────────────
                        ROBUSTNESS OBJECTIVE
───────────────────────────────────────────────────────────────────
  Function: calculateRobustnessCV()
  
  Rule: The solver calculates the Coefficient of Variation (CV) of "slack" 
        across the timetable. Slack is defined as how many *other* empty
        slots a scheduled class could potentially have been moved to.
        Lower CV means flexibility is evenly distributed across all classes,
        preventing situations where 90% of the grid is locked and 10% is empty.
