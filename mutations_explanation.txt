In your solver's code (

src/solver/mutations.ts
), the 

mutate()
 function picks between 3% and 8% of the unlocked sessions mathematically. For each picked session, it randomly chooses one of 5 different mutation operators (labeled 0 to 4 in a switch statement).

Here is exactly what each of those 5 mutators does:

OP 0: Mutate Day (

mutateDay
)
What it does: It completely changes the day of the week for the session.

Math: It picks a random integer between 1 (Monday) and 5 (Friday).
Elective Twist: If the session being moved is an Elective, the code checks if it belongs to a "synced basket" (like all the HSMC electives). If it does, it grabs all the other electives in that exact same basket and moves their days too! This ensures synced electives never get separated to different days by a random mutation.
OP 1: Mutate Time (

mutateTime
)
What it does: It shifts the start time (startBucket) forwards or backwards on the same day.

Math: It adds a random number (generated by Gaussian noise multiplied by the sigma value we discussed earlier) to the current start slot.
Limits Check: It uses a 

clamp
 function to ensure the new start time isn't mathematically impossible (like slot -2 or slot 99).
Break Crossing Check: The cleverest part! If the new, randomly shifted time causes a 2-hour lab to start right before lunch (slot 4 to 5), the crossesBreak check triggers. It forces the session to "snap" to the nearest completely safe block of time (either entirely before lunch or entirely after lunch).
Elective Twist: Just like OP 0, if an elective is shifted in time, all its synced basket-mates are shifted to the exact same start time automatically.
OP 2: Mutate Room (

mutateRoom
)
What it does: It keeps the Day and Time exactly the same, but changes the physical room assigned to the session.

How it picks: It uses the 

pickRoomForSession
 helper function, which has strict rules:
If it's a Practical (Lab), it randomly picks an ID from the list of rooms where roomType === 'Lab'.
If it's an Elective lecture, it randomly picks an ID from the list of lecture halls (because concurrent electives need different physical rooms).
If it's a Core lecture or tutorial, it completely ignores the mutation and just returns the group's predefined homeRoomIndex (hard constraint).
OP 3: Swap (

trySwap
)
What it does: It takes the selected class, finds a totally different class, and swaps their entire Day/Time schedules.

The Rules:
It searches the entire timetable for another session that has the exact same duration (e.g., swapping a 2-hour lab only with another 2-hour lab).
No Electives Allowed: It completely ignores elective subjects for swapping. Why? Because swapping an elective with a normal class would instantly break the synced clusters (e.g., Group 1's HSMC would swap to Tuesday, but Group 2's HSMC would be left behind on Monday).
Result: Class A and Class B cleanly trade places on the board.
OP 4: Relocate (

mutateRelocate
)
What it does: This is the "Nuclear Option." It completely wipes the session's current placement and assigns a brand new Day, Time, and Room all at once.

Day: Picks a random Day 1-5.
Time: Picks a 

randomSafeStart
 time (which inherently avoids breaks and boundary crossings based on duration).
Room: Uses 

pickRoomForSession
 to find the correct type of room.
Elective Twist: Again, if a synced elective is given the nuclear option, the entire synced basket is dragged along to the newly generated Day and Time (but they are allowed to keep their own separate rooms).
