The UI is designed to manage high-density data interactions without performance degradation. To achieve this, the system leverages React's virtual DOM and TypeScript's static typing.

\subsection{Performance and Data Reliability}
The system employs the \texttt{useMemo} hook to memoize expensive computations—such as $O(N^2)$ clash detection—ensuring these logic-heavy tasks only execute when the underlying timetable data changes. TypeScript is used to define rigid data interfaces, such as the \texttt{ParsedSlot}, ensuring the heuristic Excel parser outputs structured, predictable data.

\begin{verbatim}
// Example TypeScript Interface for Solver Data Contracts
interface ParsedSlot {
    id: string;
    day: string;
    startTime: string;
    subjectCode: string;
    type: 'Lecture' | 'Tutorial' | 'Practical';
    roomName: string;
    section: string;
}
\end{verbatim}

\section{Build and Styling: Vite and Tailwind CSS}

The development workflow and visual layer are optimized for rapid iteration and dynamic feedback.
\begin{itemize}
    \item \textbf{Vite:} Leverages native ES Modules for near-instantaneous hot-module replacement (HMR), critical during the refinement of grid-generation algorithms.
    \item \textbf{Tailwind CSS:} A utility-first framework that allows the system to dynamically apply visual alerts, such as red ring borders for clashing sessions, directly within the React components.
\end{itemize}

%-----------------------------------
\section{Backend and Data Ingestion: Supabase}

The system replaces static files with a centralized PostgreSQL database hosted on Supabase, ensuring referential integrity through foreign key constraints.
\begin{itemize}
    \item \textbf{Heuristic Parsing:} The \texttt{xlsx} (SheetJS) library is used to read raw institutional spreadsheets. These are processed by a custom engine to extract semantic meaning, such as L-T-P credit structures and complex faculty assignments.
    \item \textbf{Authentication:} Secure access for administrators is managed natively by Supabase Auth, with state handled via a global \texttt{AuthContext} provider.
\end{itemize}

%-----------------------------------
\section{Solver Engine: Pure TypeScript Architecture}

The core contribution of this system is its pure-TypeScript solver engine, which runs directly in the browser. This eliminates the need for server-side optimization and allows for real-time schedule generation. The solver is organized into discrete submodules:

\begin{itemize}
    \item \textbf{\texttt{dataPrep.ts}}: Expands high-level credits into individual sessions and applies the 2+1 lecture format.
    \item \textbf{\texttt{constraints.ts}}: Evaluates solutions against ten hard and three soft constraints.
    \item \textbf{\texttt{mutations.ts}}: Implements five mutation operators, including day reassignment and Gaussian time shifts.
    \item \textbf{\texttt{solver.ts}}: Manages the (1+1)-ES loop, elitist selection, and stagnation restarts.
    \item \textbf{\texttt{localSearch.ts}}: Provides the LNS auto-fix routine for the interactive editor.
\end{itemize}

%-----------------------------------
\section{External Integrations: Reporting and Export}

To support administrative workflows, the system integrates with external reporting tools:
\begin{itemize}
    \item \textbf{Google Sheets API:} Exports formatted schedules with frozen headers and color-coded session types directly to Google Drive.
    \item \textbf{PDF Generation:} Captures high-fidelity snapshots of the timetable grid using \texttt{html-to-image} and \texttt{jsPDF} for immediate offline use.
\end{itemize}
