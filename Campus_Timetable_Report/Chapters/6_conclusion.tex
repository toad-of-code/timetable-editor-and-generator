This project replaced the manual, spreadsheet-driven scheduling process at IIIT Allahabad with a web-based platform for the automated generation and management of university timetables. The system provides a centralized environment for data ingestion, conflict-aware editing, and automated scheduling using evolutionary algorithms.
%-----------------------------------
\section{Summary of Contributions}

Key outcomes of the project include the development of a working scheduling system featuring the following:
\begin{itemize}
    \item \textbf{Heuristic Ingestion Engine:} A parser for Excel sheets using \texttt{SheetJS} to normalize unstructured data into the PostgreSQL database containing subject information, faculty allocations, and credits.
    \item \textbf{Conflict Detection Algorithm:} A multi-dimensional $O(N^2)$ algorithm which detects conflicts based on rooms, faculties, and students' classes, as well as whole-batch (WMC) constraints.  \item \textbf{Evolution Strategy Solver:} A (1+1)-ES implementation that evaluates schedules against ten hard and three soft constraints. It utilizes Rechenberg's 1/5th success rule for adaptive mutation control and a stagnation restart mechanism.
    \item \textbf{Interactive Editor:} An interactive editor that employs drag and drop along with the React framework, including the visualization of conflicting sessions and LNS for automatic fixing of problems.
    \item \textbf{Multistep Configuration Process:} A multistep configuration process where users specify semester groupings, assign home rooms, allocate teachers, and run the solver afterward.
   \item \textbf{Independence of Sessions Across Semesters:} Blocking of sessions from earlier schedule releases to prevent any clashing classrooms or lecturers across courses.    
\item \textbf{Architecture:} The system will be built using a scalable architecture involving React 19, TypeScript, and Vite on the frontend, and Supabase for authentications and database storage of related data.
\item \textbf{Exports:} Support for client-side PDF export and Google Sheets exports for administrative purposes.\end{itemize}

\section{Future Work – Phase 2 – Integration with M.Tech}

The first step in future development will be the integration of M.Tech courses within the automatic solver. The complexity of the algorithm will increase because of a paradigm shift from one-tier scheduling to multi-tier scheduling having interdependencies amongst itself, i.e., the ``Basket Tethering'' Problem.

\subsection{The Basket Tethering Problem}

The three specializations of M.Tech courses (MLIS, HCI, and CLIS) do not operate independently of each other in the respect that they tend to select courses in certain “baskets” offered under B.Tech VIth sem. The consequence of such selection is that the M.Tech schedules are dependent on those of the B.Tech, such that M.Tech can only be scheduled after specific time-slots have been allocated. The future plan will be to adopt a hierarchical solving approach by assigning anchors as common windows amongst the two schedules.

\subsection{Solving Core Duality}

There are many instances where there exist core duality in courses as some M.Techs consider a subject as core for themselves while for others it is elective (for example: Deep Learning and NLP). The next task is to schedule the dual course once.

\subsection{Meta-Grouping and Collision Handling}

In order to handle the added complications of the scenario, the following meta grouping method is suggested.


\begin{itemize}

    \item The specializations would be grouped into disjointed meta-groups (e.g., Meta-Batch A = \{MLIS, RMI, HCI\}) based on the common subject area they share.

    \item A sequence of steps for addressing the issue of the ``Three-Way Collision'' should be determined.

\end{itemize}

\subsection{Scalability of Algorithmic Solution}

Given the growing number of constraints because of the inclusion of M.Tech subjects, it is possible that the $(1+1)$-ES algorithm would need to be reworked with parallel computing using Web Workers or by merging ES and CP.

\subsection{Technical Requirements at the Core}

\begin{itemize}

    \item \textbf{Requirement:} Integration of M.Tech specialization courses within the same framework of B.Tech course structure without any conflict.

    \item \textbf{Algorithms:} Give preference to Hierarchy solution: Anchors $\rightarrow$ M.Tech Core $\rightarrow$ B.Tech Core $\rightarrow$ Soft Constraints.

    \item \textbf{Conflict Handling:} Solve the ``Three-Way Clash" problem, avoiding any schedule conflict for instructors working at different levels.

\end{itemize}

\section{Conclusion}

Timetabling System for IIITA shows that complex issues of timetabling in university settings can be resolved through the use of web technology. The timetables produced by the (1+1)-ES algorithm are consistent with the provided constraints, whereas any manual modification can be performed within the editor application. A serverless approach to processing data with the help of the TypeScript version of the solver is appropriate for educational organizations.
